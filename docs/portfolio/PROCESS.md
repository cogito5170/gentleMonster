# 자기소개서 제작 프로세스 (혁주 표준)

젠틀몬스터 공간 설계 디자이너 지원서 문항 2(1164자)와 문항 1(865자)을 초안부터 완성본까지 만든 과정(CMD-HJ1~HJ43)을 정리한 표준 절차다. 새 자기소개서는 이 순서로 만든다. ATiiSSU 공고(CMD-HJ44~45)에서 확인한 "다른 회사로 옮기기" 절차도 함께 둔다.

- 운영 규약(세션·메시지 형식): [agent_protocol.md](agent_protocol.md)
- 작성 문법 G0~G8: `handoff/CMD-HJ3.result.json#writing_grammar`
- 약점 유형 W1~W3·WG1~WG7: [weakness_cases/analysis.md](weakness_cases/analysis.md)
- 사실 원천: [context_handoff.md](context_handoff.md), [cover_letter.md](cover_letter.md), [01_style.md](01_style.md)

## 0. 원칙 (모든 단계에 적용)

| 구분 | 규칙 |
|---|---|
| 사실 | 경험·성과·수치·동기·감정은 지어내지 않는다. 사실이 없으면 **사용자에게 묻는다**(빈칸 또는 보수적 임시 문장 + 질문). |
| 문체 | 합니다체. 지칭어(저는·제가·저를) 없음. 추상·감정어와 막연한 다짐(성장·최선·노력·열정) 없음. |
| 문장 | 한 문장 한 생각, 대체로 60자 안팎. 80자를 넘으면 두 문장으로 나눈다(G7의 '90자' 기준보다 이 기준이 우선). 쉼표로 줄줄이 잇지 않는다. |
| 결정권 | 통째로 다시 쓰지 않는다. 부분만 고치고 대안을 준다. **고르는 것은 사용자다.** 사용자가 문장을 직접 주면 그대로 반영한다. |
| 글자 수 | 공백·줄바꿈 포함 `len()`. 수정할 때마다 전문과 글자 수·남은 글자를 보여 준다. |
| 거절 소재 | 이솝, 알바 알토/아르텍, "내 눈은 늘 그 안에 머물렀다", "도전하지 않으면 아쉬울 것 같아", "손으로", AI 도구(클로드·챗GPT) 언급. 문항에 따라 다른 것: 홍대점 이야기·설계 프로젝트 내용은 젠틀몬스터 문항 2(자기소개)에서는 쓰지 않았고, 문항 1(지원동기)에서는 사용자 원고라 썼다 — 문항마다 사용자에게 확인한다. |
| 사실 수위 | 실제보다 세게 쓰지 않는다. 예: "'중력의 계단'으로 풀었다" → "참고해 계획했다". |

## 1. 준비

1. **공고 원문 저장**: `docs/portfolio/postings/<회사>_<직무>.md`. 사이트에 접속할 수 없으면 사용자에게 본문을 붙여 달라고 한다.
2. **문항·글자 수 확정**: 문항 원문, 제한(없으면 "제약 없음"), 문항 수.
3. **사실 원천 확인**: 위 사실 원천 파일을 읽는다. 새로 받은 사실은 `context_handoff.md`에 더한다.
4. **기록 파일 만들기**: `handoff/selection_<문항>.json`(current_text, limit, edits 로그, status).

## 1-B. 기업·브랜드 분석 (사용자와 단계별로)

기사·매거진·영상·공식 채널로 브랜드의 방향성·이미지·가치관(대표의 가치관)을 분석한다. 결과는 `docs/portfolio/brand/<브랜드>/`.

| 단계 | 하는 일 | 사용자 |
|---|---|---|
| B1 대상·범위 | 브랜드·모회사 관계, 기간(기본 최근 3년), 관점(공간 전략 등) | 확정 |
| B2 자료 수집 | 매체별 출처 표(날짜·매체·원문 확인 여부·신뢰도) | 자료 추가·선별 |
| B3 발언·키워드 | 대표·디렉터 직접 인용, 반복 키워드, 매장·캠페인 사례 | 인상 깊은 것 고르기 |
| B4 분석 | 방향성 / 이미지 / 가치관 / 공간 전략 | 해석 확인 |
| B5 사용자 연결 | 브랜드 가치와 사용자 경험·지향의 겹침·차이 | 직접 경험 추가 |
| B6 결과물 | 한 장 요약, 자기소개서 근거, 면접 질문, 쓰면 안 되는 미확인 사실 목록 | 확정 |

- 출처 없는 브랜드 사실·대표 발언은 쓰지 않는다. 검색 요약만 있는 것은 '원문 미확인'으로 표시한다.
- 브랜드를 둘러싼 분쟁·논란이 있으면 별도 맥락으로 기록하고, 자기소개서·면접에서 다룰지 사용자가 정한다.

## 1-C. 우수 사례 참고 (중간 단계, 사용자가 사례를 가져올 때)

같은 회사·계열의 자기소개서 사례를 모아 우수 사례를 추리고, 사용자 유형과 닮은 사례를 따로 고른다. 기록은 `docs/portfolio/references/<회사>_samples/`.

| 단계 | 하는 일 | 사용자 |
|---|---|---|
| C1 수집 | 사례 이미지·텍스트를 받아 ID(S1…)를 붙이고 회사·직무·소제목·핵심 경험을 표로 | 사례 제공 |
| C2 우수 사례 선별 | 기준표(구체성·수치, 소제목, 첫 문장, 직무 연결, 막연한 다짐 없음)로 점수 매겨 추림 | 확정 |
| C3 유형 유사 사례 | 사용자와 배경·경험 규모·직무가 닮은 사례, 빌릴 수 있는 구성 방식 | 고르기 |
| C4 적용 | 빌릴 것은 구성·전개·소제목 방식만. 타인의 문장·경험·수치는 쓰지 않는다 | 확인 |

참고 사례: 신세계 계열 12개(2026-10-14), `references/shinsegae_samples/`.

## 2. 공고 분석 (분석 세션)

참고 사례: CMD-HJ44.

- **담당업무 축 나누기**: 예) 기획·제안 / 설계·도면 / 감리·설치. 자격·우대에서 반복되는 낱말(예: "현장" 3회)에 무게가 있다.
- **적합도 표**: 요구 항목마다 사실 근거, 판정(충족·부분·공백·확인 필요), confidence.
- **공백 → 사실 확인 질문**: 분석 세션이 공백마다 짧은 질문을 만들어 결과 파일·report/2 blockers로 허브에 넘기고, 허브가 사용자에게 묻는다(AskUserQuestion 4개 이내 + 나머지는 목록).
- **회사 고유 vs 재사용**: 이미 완성한 다른 회사 자기소개서가 있으면 그대로 쓸 부분과 바꿀 부분을 표로 나눈다.
- **면접·과제 예상 질문** 5~7개.

## 4. 구조 확정

젠틀몬스터 두 문항에서 굳힌 틀:

```
〈소제목: 한 줄 비유〉
① (문항 첫째 물음) — 첫 문장이 답(두괄식)
② (문항 둘째 물음) — "첫째, X입니다." 항목: 머리말 → 사실 근거 → 직무 연결("~하겠습니다")
   (약점/보완 문단은 ② 끝에)
③ 포부 한 문장 — 소제목·①을 되받는다 (또는 ② 끝에 붙임: 사용자 선택)
```

- 문항 핵심어를 그대로 되받는다(G1).
- 공고의 담당업무·자격·우대 줄마다 대응 문장이 있는지 표로 확인한다(G1).
- 문항이 둘 이상이면 문항끼리 소재·문장·포부 짜임이 겹치지 않게 한다.

## 5. 문장 단위 다듬기 (반복 루프 — 작업의 대부분)

```
사용자가 걸리는 문장·이유를 짚음
  → 허브: 입력 JSON(target_text, 전문, 앞뒤 문맥, keep, 사용자 사실, 관찰) 작성
  → 편집 세션: 대안 3~5개 (각각 유형·한 줄 설명·전문·len·증감) + 추천과 이유
  → 허브: 전문이 원문과 target만 다른지 검증 → 표로 제시 + 허브가 본 추가 문제점
  → 사용자: 채택 / 섞기 / 직접 문장 제시 / 되돌리기
  → 허브: 원고에 반영 → 전문 + 글자 수 + 다음에 볼 곳
```

대안은 **유형이 서로 달라야** 한다(같은 뜻의 낱말만 바꾼 5개는 안 된다). 젠틀몬스터 작업에서 자주 쓴 점검 관점:

| 관점 | 무엇을 보나 | 실제 예 |
|---|---|---|
| 흐름 | 주어가 오락가락하는가, 체감과 이유가 떨어져 있는가 | 계단 → 스케일 → 계단 (CMD-HJ30) |
| 사실 수위 | 실제보다 세게 썼는가 | "풀었다" → "참고해 계획했다" |
| 구체성 수위 | 분야 밖 독자에게 너무 구체적인가 | 학년·지명·"2층·지하층·코어" 삭제 (CMD-HJ28·29) |
| 공고 정합 | 담당업무와 부딪히는가 | "제품이 아니라" ↔ 오브제·가구 업무 (CMD-HJ34) |
| 면접 방어 | 이 문장이 부를 질문에 사실로 답할 수 있는가 | "드뭅니다" 비교 근거, "안경 없는 팝업은?" (CMD-HJ35·39) |
| 브랜드 정합 | 회사의 핵심 제품·형태를 빠뜨리거나 좁히는가 | 안경 포함, "안경이든 브랜드든" (CMD-HJ38·39) |
| 반복 | 같은 낱말이 가까이 겹치는가 | 계단 3회, 공간·설계 반복 |
| 길이 | 한 문장이 길거나 쉼표가 많은가 | H2 119자 → L4 두 문장 (CMD-HJ40) |
| 사용자 지향 | 사용자가 추구하는 가치를 담았는가 | "모든 요소가 어우러져 하나의 장면" (CMD-HJ41) |

## 6. 약점 문단

1. 문항이 약점을 묻는지 확인한다(묻지 않으면 W3 생략도 가능).
2. 유형 선택: W1 강점의 그림자형 / W2 장면 극복형 / W3 중화·생략형. 공통 문법 WG1~WG7을 따른다.
3. 5케이스(WC1~WC5) → 사용자가 조합(예: WC1+WC5).
4. 다듬기 원칙:
   - "약점"이라는 낱말 대신 "채워야 할 부분", "보완할 점"을 쓴다.
   - 지금 실제로 하고 있는 보완 행동(사실)을 쓴다. 학원·자격증처럼 사실이 아닌 보완책은 쓰지 않는다.
   - 회사 전제가 바뀌면 약점도 바꾼다(젠틀몬스터: 절제/과감 → ATiiSSU: 현장 경험).

## 7. 포부·맺음

- 다짐 대신 **할 일**이나 **설계하고 싶은 공간의 장면**으로 닫는다.
- 다른 문항의 포부와 짜임·낱말이 겹치지 않게 한다(예: "…디자이너가 되겠습니다"가 이미 있으면 다른 짜임으로).
- 순서: 1차 5안(서로 다른 유형) → 필요하면 "더 강한 유형" 5안 → 사용자 선택.
- 배치는 두 가지를 보여 준다: (가) 앞 문단 끝에 붙임 / (나) "③ 포부" 소제목.

## 8. 마감 점검

- [ ] 글자 수 제한 안
- [ ] 첫 문장이 문항의 답(G2), 문항 핵심어 되받기(G1)
- [ ] 공고 담당업무·자격·우대 대응 표
- [ ] 모든 주장에 면접에서 댈 사실이 있음(G3)
- [ ] 다른 문항과 겹치는 문장·소재 없음
- [ ] 다른 회사 고유 표현 없음(회사 이름, 대표 제품, 디자인 언어 전제)
- [ ] 가까이 반복되는 낱말 정리
- [ ] 사용자 "완료" 선언 → `selection_*.json` status complete → `cover_letter.md`·`context_handoff.md`에 완성본 기록 → 커밋·푸시

## 9. 다른 회사로 옮기기 (재활용)

1. 2단계 공고 분석 + 회사 고유/재사용 표.
2. 사실 확인 질문(툴 수준, 현장 경험, 브랜드 직접 경험, AI 언급 여부 등)을 먼저 받는다.
3. 회사 고유 장면은 이름을 빼거나 삭제한다. 브랜드를 직접 본 적이 없으면 브랜드 사실은 쓰지 않고, 공고 문구(팀 소개·담당업무)만 근거로 쓴다.
4. 강점 순서를 공고가 무겁게 보는 순서로 바꾼다(예: 실행·툴 중심 공고 → 구현·툴을 첫째로).
5. 같은 그룹사에 함께 낼 때는 똑같은 문장이 겹치지 않게 한다.
6. 초안 A1 + 막힌 곳 질문(BQ) → 5단계 루프로 다듬는다.

## 부록 A. 운영 (허브 ↔ 세션)

| 단계 | 세션 | 산출물 |
|---|---|---|
| 공고 분석, 원고 진단, 5유형 설계 | 분석 (Context Analysis) | `CMD-HJn.result.json` (분석 브랜치) |
| 집필, 대안, 교정 | 편집 (Editor_Writer) | `CMD-HJn.result.json` (편집 브랜치) |
| 채택 반영, 사용자가 준 문장 반영, 표시 | 허브 (혁주 작업 공간) | `selection_*.json`, 커밋 |

1. 입력 JSON 작성 → 커밋·푸시 → sha 확보
2. `directive/2`를 만들고 검증(`python3 -I`, `/`에서 실행) → `send_message` + 대비용 `send_later`
3. 지시 원문 커밋
4. `report/2` 수신 → 결과를 `git show <sha>:<path>`로 복사
5. 대안 전문이 원문에서 target만 바꾼 것인지 확인
6. 커밋, 대비 트리거 삭제
7. 사용자에게 결과만 표시: 진단 요약, 전·후, 대안 표, 글자 수, 고를 것

## 부록 B. 사용자 선호 (젠틀몬스터 작업에서 확인)

- 자기 문장을 직접 주고 섞는 일이 많다 → 그대로 반영하고, 맞춤법·띄어쓰기만 지적한다.
- 마음에 들지 않으면 이전 판으로 되돌린다 → 모든 판을 `edits` 로그에 남긴다.
- 건축 전공 밖 지원서에서는 건축 실무 용어·학년·지명을 줄이고 함축하는 쪽을 고른다.
