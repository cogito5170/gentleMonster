# 단점 답변 유형 분석 (CMD-HJ7)

분석: Context Analysis 세션. 원문 JSON은 `../handoff/CMD-HJ7.result.json`에 있고, 사례 원문은 `sources.md`에 있다.

## 유형 3가지

| 유형 | 사례 | 구조 | 필수 요소 | 쓸 때 위험 |
|---|---|---|---|---|
| W1 강점의 그림자형 | 사례 1 (간호, 공감) | 강점 → '반면' 단점 → 직무 위험 → 보완 행동 → 결과 → 강점과 보완을 묶은 맺음 | 강점과 같은 뿌리, 직무 위험, 과거형 보완, 결과 | 결과를 자기 관찰로만 쓰면 약함. 자랑이나 회피로 읽힐 수 있음 |
| W2 장면 극복형 | 사례 3 (간호, 낯가림) | 단점 정의 → 범위 한정 → 계기 장면 → 직무 위험 → 구체 보완 동작 → 타인 반응 → 습관화 → 맺음 | 범위 한정, 계기 장면, 구체 보완, 바깥 확인 | 직무 핵심 역량의 결핍을 고르면 치명적. 사실이 없으면 쓸 수 없음 |
| W3 중화·생략형 | 사례 2 (회계) | 여러 모습 → 단점에 가까운 면을 같은 문장에서 장점으로 뒤집기 → 강점으로 모으기 | 문항이 단점을 필수로 묻지 않을 것 | 단점을 묻는 문항에서는 회피로 읽힘 |

## 공통 문법 WG1~WG7

1. 단점은 직무 핵심 역량의 결핍이 아니라 성향, 강점의 과잉, 상황에 한정된 모습으로 고른다.
2. 단점은 숨기지 않고 한 문장으로 먼저 말한다.
3. 왜 고쳐야 하는지 직무 위험을 한 문장으로 인정한다.
4. 보완은 이미 한 행동(과거형)으로 쓴다. '하겠다'만으로는 보완이 아니다.
5. 결과는 지금의 변화로 보인다. 타인 반응이 있으면 가장 강하다.
6. 지원 회사와 맞지 않는다는 말은 쓰지 않는다. 보완된 모습으로 닫는다.
7. 분량은 문항이 단점에 주는 비중을 따른다: 단독 문항 87%, 강점과 짝 47%, 선택·예시 0~2%.

## 사용자 약점 문단 판정

- 사용자 문항은 단점을 묻지 않는다(사례 2와 같은 처지). 넣는다면 짧게(전체의 12~15%)가 맞다.
- R-A·R-B·R-C 모두 W1 계열이다. 가까운 순서는 R-C 0.72, R-B 0.70, R-A 0.62.
- 있는 것: 단점 한 문장, 범위 한정(해 본 적 없음 + 건축에서 절제를 익힘), 직무 연결(톤을 맞추는 역할).
- 빠진 것: 과거형 보완 행동(M1), 결과(M2), 계기 장면(M3). 젠틀몬스터 구절을 뺀 판은 직무 위험 문장도 빠진다.
- 세 사례에 없는 장치: 약점을 바로 기여로 뒤집는 '톤을 맞추는 역할'. 보완·결과 없이 기여로 넘어가면 '약점을 장점으로 말 바꾸기'로 읽힐 수 있다(신뢰도 0.55).
