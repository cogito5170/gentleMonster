# 짧은 후속 지시와 불만족 — 방향과 성공 기준

2026-10-15 · 이 문서와 `eval/followup_cases.json`(정답 표)은 **코드보다 먼저** 커밋한다. 결과를 보고 기준을 고치지 않기 위해서다.

## 1. 문제 (재현된 것만)

`/mnt/project-files/scenario1` 을 main `6acff99` 에서 다시 돌린 결과(자소서 사례 → 문항 → "고쳐" / "피드백 해봐" 반복):

| 증상 | 원인 (`context.py` / `memory.py`) |
|---|---|
| "고쳐" 턴에 **직전 초안이 빠진다** | 모델 출력은 `key` 가 `draft…` 이거나 지시와 낱말이 겹칠 때만 남는다. "고쳐" 는 겹칠 낱말이 없다 |
| 몇 턴 뒤 **사례와 문항이 빠진다** | 오래된 사용자 말은 최근 4턴 · 낱말 겹침 · (명령 + 공간 낱말) 일 때만 남는다. 최근 4턴을 "고쳐" 가 채운다 |
| "고쳐" 가 **USER CORRECTIONS — override everything** 아래 들어간다 | `CORRECTION_CUE` 에 고쳐 · 잘못 · 틀렸 이 있어서, 새 값이 없어도 정정으로 표시된다 |
| "폭이 틀렸잖아" 같은 **근거 없는 비판**도 정정 자리에 놓인다 | 같은 원인. 원자료가 폭 20m 를 받쳐도, 모델은 "이걸 따르라" 는 자리에서 불만을 본다 — 아첨(뒤집기)을 부르는 입력이다 |

## 2. 원칙

**확인된 것은 새 근거가 있을 때만 바뀐다. 불만은 근거가 아니다.** (`promote()` 가 모델 말만으로는 사실이 되지 못하게 막는 것과 같은 규칙을 사용자 쪽에 적용한다.)

## 3. 구조 — try / throw / catch / finally

- **try**: 답은 출처가 붙은 주장으로 낸다 (지금 그대로: 사용자 말 · 원자료 · 미검증 모델 출력을 나눠 보인다).
- **throw**: 불만 신호가 오면 `memory.classify()` 가 네 갈래로 나눈다. 모델 호출 없이 코드로만 한다.

  | 갈래 | 예 | catch: 모델에게 주는 지시 |
  |---|---|---|
  | `correction` 근거 있는 변경 | "벽은 콘크리트 말고 나무로", "폭 18m로" | 반영한다. 옛 값은 superseded (지금 동작 그대로) |
  | `bare` 이유 없는 평가 | "고쳐", "재미없어", "마음에 안 들어" | 직전 초안을 기준 자료와 마지막 피드백에 대 보고 스스로 진단한다. 가정을 한 줄로 밝히고 고친다. 근거 없는 사실을 새로 넣지 않는다 |
  | `unsupported` 확인된 사실에 대한 근거 없는 비판 | 원자료가 폭 20m 인데 "폭이 틀렸잖아" | **바꾸지 않는다.** 근거(누가 · 어디서)를 보이고 어느 부분이 왜 틀렸는지 한 번 되묻는다 |
  | `unclear` 대상이 불분명 | 초안이 없는데 "고쳐", 초안이 있는데 "틀렸어" · "이 부분 이상해" | 한 번만 묻는다: 무엇을 어떻게 |

- **finally**: 판정 갈래와 대상 키를 trace(`context_trace.jsonl`)에 남긴다. 무엇이 왜 바뀌었는지는 기존 superseded 링크가 이미 남긴다.

함께 고치는 맥락 선택:

1. **작업 대상 포인터.** 가장 최근의 모델 출력은 항상 넣는다(`MODEL'S EARLIER OUTPUT — UNVERIFIED` 아래, 맨 앞). 짧은 후속 지시가 가리키는 것이 그것이다.
2. **기준 자료 고정.** 사용자가 붙인 긴 자료("아래 … 참고해", 문항, 원문)는 `pinned` 로 표시하고 4턴이 지나도 뺀다고 판정하지 않는다(예산 안에서).
3. **최근 창에서 빈 턴 제외.** "고쳐" 같은 12자 이하의 불만 턴은 최근 4턴의 자리를 차지하지 않는다.
4. **정정 표시를 좁힌다.** `correction` 은 새 값(`A 말고 B`, 또는 읽힌 슬롯)이 있을 때만 true.

effiency 보관소(relay)에 대한 같은 종류의 수정 — `general` 도메인이 전 도메인을 검색하지 않게, "고쳐" 같은 흔한 동사만 겹칠 때 다른 세션 기록을 붙이지 않게 — 은 그 저장소의 PR 에서 따로 잰다.

## 5. 무효화 조건 · 못 재는 것

- **모델이 실제로 덜 뒤집는지는 재지 않는다.** 위 기준은 "뒤집기를 부르는 입력이 사라졌나" 까지다. 실제 아첨률은 모델을 불러 재야 하는데, 이 저장소의 모델(Gemini)은 무료 정책 변경으로 빠졌다. 모델 수준의 숫자가 나오기 전에는 "아첨을 줄였다" 고 말하지 않는다.
- 분류기는 정규식이다. 정답 표에 없는 말투에서는 틀린다. C6 이 90% 를 넘어도 그것은 이 표에서의 수다.
- 정답 표는 내가(구현한 쪽이) 썼다. 바깥 사람이 쓴 표로 다시 재기 전에는 낙관 쪽으로 기운 수일 수 있다.
